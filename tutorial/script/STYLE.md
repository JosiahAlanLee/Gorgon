# Narration style

The docs this video follows are plain and exact. The narration should be too.

- Say what a thing does, in the order a person meets it. One idea per sentence.
- Use the interface's own words, spelled as it spells them: **Seek to row**,
  **Piano keys**, **Save session**, **CV 1 drives**. Panel labels in capitals
  where the panel prints them (CLOCK, RESET, OPT).
- No hype, no "powerful", "seamless", "simply", "just", "magic". No "we" doing
  things the viewer does; address the viewer as "you" only when giving an
  instruction.
- State limits where they matter, once, without apology: the browser synth is a
  demo; Dolly Z is 2D scale; the chain plays pattern codes in order; hardware isn't shown.
- Numbers as the docs give them, with their conditions ("about twenty
  milliseconds at 48 kHz with 256-frame periods"), or as the stage measured
  them, said as such.
- Cues (`{name}`) go before the word the action should land on. Leave half a
  second of narration after a cue that starts something visible.
- A shot's narration fits its pictures: if the actions need nine seconds, the
  sentences around them need about that too. Don't pad with filler; add a `hold`
  or a `wait` instead.
- Write for the ear: avoid parentheses and long lists; spell out symbols the
  voice would read badly, or add them to `narration.lexicon`.
